# 会话续聊与权限

项目任务默认完全访问，可在插件设置选择询问或自动审批。会话时限为 1–24 小时，默认 2 小时，按最近成功投递计算。不同 Bot、联系人及执行配置独立；插件重启后新建会话，Bot 长期记忆持久保留。微信项目说明模板见 wechatBot-AGENTS.md，实际已写入相邻 wechatBot/AGENTS.md。

# 默认项目和 Bot 记忆

## 0.4.2（2026-11-15）

新增 Bot 级 mode（project/companion）与可选 execution 模型覆盖。未显式选择的旧配置保留原有行为；显式 companion 不受全局默认项目影响。项目模式继承全局项目与模型，Bot execution.route 可独立覆盖完整模型、供应商、框架、推理档位和 Fast，route:null 表示恢复继承。收到输入时固定有效执行配置。当前请求未结束时拒绝修改此 Bot 路由，名称与启停保留路由字段。

UI 每个 Bot 都有回答方式选择，以及项目模式独立选模和恢复默认按钮。转接伙伴的编辑和说明入口按 Bot 显示，不再被全局项目设置隐藏。既有伙伴一对一绑定限制保持。

## 0.4.1（2026-11-15）

项目和模型选择后各自立即保存，二者齐全才启用项目路由。默认自动读取项目，并显示目录以区分同名项目。“选择目录”经 workspace 登记执行电脑上的项目，传递本次 mobilePageId，让远程页面显示目录和模型选择器。登记会保留一个可见空任务，不执行模型。workspace 是本版新增权限。

记忆迁移为插件 data 根目录下的 `bot-memory-<Bot ID>.json`，每个 Bot 独立文件，最多 4000 字。0.4.0 KV 摘要先迁移成功再移除旧副本。Bot 卡片显示字数，并提供手动清空；清空持久提升修订号，清空前已运行的请求不能写回旧摘要。重命名不改变分区。清空不更改登录或其他 Bot。

设置读取、选择和记忆清空不依赖 Node 启动成功。失败时仍显示保存的 Bot 名称与明确启动错误，可手动重试进程。旧绑定兼容保留。

实际运行宿主现为 Cindy 0.1.136。2026-11-14 22:11:46 的宿主日志中，微信 Node 在 10 秒期限内只有 utility-process-spawned，messageCount=0、readySeen=false；尚未执行插件 configure 或登录恢复。QQ 与浏览器插件也有同类记录。本次修复设置阻塞，不声称修复宿主原生启动故障；没有删除登录或要求重新扫码。

验证包含打包后的主逻辑、真实 BotManager 与模拟宿主，覆盖失败启动仍可设置、远程来源转交、目录选择即保存、记忆迁移及单 Bot 清空/旧请求拒写。真实远程选择器及微信端到端仍需宿主启动恢复后验收。

## 0.4.0 历史行为

在插件设置中读取项目、选择模型与推理档位，然后保存。全部 Bot 的后续输入使用这份配置。尚未保存时，已有绑定继续使用原伙伴。新增 Bot 在项目模式中扫码后直接启用，无需再选伙伴；既有登录与绑定保留。

每条输入创建独立项目任务，正文保持原文；来源、回传编号及该 Bot 的摘要通过 Host context 传入。排队和重试保留接收时的项目/模型快照。项目任务不能使用插件配置或主动发送工具。

简单长期记忆由任务调用 remember_wechat 更新，最多 4000 字，按稳定 Bot ID 分区，保存于插件 KV，重启恢复。空字符串清空。不是自动保存全部聊天，也不是文件系统安全隔离；同一项目的普通任务权限仍由 Cindy 管理。不要保存密码、令牌或整段历史。
